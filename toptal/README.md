# Toptal

If you go through Toptal's screening and are accepted into the network, this
folder tracks everything **after** acceptance: profile setup, applying to
eligible jobs, then running client engagements. The screening process itself
is worth its own notes under `interviews/prep/toptal/` once you're through it.

This is one example of a "platform/network" track alongside your direct job
search — the same pattern applies to any other talent network or agency you
join (Turing, X-Team, etc.): keep its status and rules here, reuse your core
material (résumé, answers) from the shared files.

## What's here

```
README.md                        # this file — status + how to use the folder
rules.md                         # the rules you're bound by, distilled (rates, recruiter, NDA, trial)
profile.md                       # public profile + rate + availability: state and decisions
onboarding/                      # verbatim onboarding material once accepted (source, immutable)
applications/                    # one file per Eligible Jobs application (see its README)
engagements/                     # one folder per client engagement once won (see its README)
```

## How this connects to the rest of the repo

A platform track like this runs **parallel** to your direct job search, not
as a replacement. Material is shared, framing is not:

- Résumé content and bullets: [`../profile/experience-bank.md`](../profile/experience-bank.md)
  and the pivots in `../resumes/`. Write the platform profile from the same
  material, not from scratch.
- Reusable application answers: [`../answers/bank.md`](../answers/bank.md).
- Interview prep: [`../interviews/`](../interviews/) — client interviews arranged
  through the platform use the same prep and feedback log.
- **Confidentiality cuts across**: platform jobs and client work often can't
  feed public content like `../linkedin/`. See `rules.md` and set your own
  boundary explicitly.

## Working rules for future sessions

1. Read `rules.md` before drafting anything that goes to a client or a
   recruiter — rate and process rules are easy to break by accident.
2. Anything sent to a platform or a client is external-facing writing → run it
   through the `writing` skill / tropes filter.
3. Decide up front whether rate figures go in client-facing messages at all —
   many platforms require rate to stay platform-only.
4. Applying to a job = create the file in `applications/` at the same time,
   from the template in its README. Same for winning an engagement in
   `engagements/`.
5. **Client data and NDA material do NOT get committed to this repo** — keep it
   in the engagement's own workspace outside this repo, and reference it by
   path only.
